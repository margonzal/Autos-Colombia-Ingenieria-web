# Desarrollo del sistema web – Autos Colombia

Actúa como desarrollador full stack y ayúdame a construir un sistema web funcional para la gestión de un parqueadero llamado **Autos Colombia**.

Es un proyecto académico para la asignatura Ingeniería de Software de Tecnología en Desarrollo de Software. El desarrollo se realiza por iteraciones, por lo que es importante mantener una estructura organizada y permitir futuras ampliaciones.

## 1. Tecnologías

Utiliza las siguientes tecnologías:

- Frontend: React.
- Backend: Node.js con Express.
- Base de datos: MySQL.
- Conexión entre frontend y backend mediante API REST.
- CSS para los estilos de la interfaz.

No cambies estas tecnologías.

## 2. Descripción del sistema

Autos Colombia es un parqueadero que presta servicios de parqueadero por mensualidad.

El sistema será utilizado exclusivamente por el personal del parqueadero. Los clientes propietarios de los vehículos NO tendrán acceso ni podrán iniciar sesión.

El sistema debe permitir administrar:
- Vehículos.
- Entradas y salidas de vehículos.
- Usuarios internos del sistema.
- Celdas del parqueadero.
- Historial de movimientos.
- Novedades de los vehículos.
- Pagos (se desarrollarán en una iteración posterior).

## 3. Diseño de la interfaz

Quiero una interfaz moderna, profesional, limpia y fácil de utilizar.

Toma como referencia un sistema administrativo de parqueadero, con las siguientes características:

- Menú lateral izquierdo de navegación.
- Barra superior con nombre del módulo y usuario conectado.
- Panel principal con tarjetas informativas.
- Tablas para mostrar registros.
- Formularios para crear y editar información.
- Botones claros para las acciones.
- Mensajes de confirmación y validación.
- Diseño adaptable a diferentes tamaños de pantalla.

Utiliza una combinación de azul oscuro, azul claro, blanco y gris, similar al diseño que ya tengo realizado en Figma para la primera iteración.

No quiero una página comercial ni una landing page. Necesito un sistema administrativo real.

## 4. Módulos del sistema

### A. Inicio
Crear un panel principal que muestre:
- Cantidad de vehículos actualmente en el parqueadero.
- Entradas registradas durante el día.
- Salidas registradas durante el día.
- Cantidad de celdas disponibles.
- Cantidad de celdas ocupadas.
- Movimientos recientes.

### B. Gestión de vehículos
Permitir:
- Registrar vehículos.
- Consultar vehículos por placa.
- Visualizar información del vehículo.
- Consultar su estado actual.

Datos: placa, marca, modelo, color y estado.

### C. Registro de entrada
Permitir:
- Buscar un vehículo por su placa.
- Mostrar sus datos.
- Registrar la fecha y hora de entrada.
- Asociar el movimiento con una celda disponible.
- Validar que el vehículo no tenga un movimiento abierto.

### D. Registro de salida
Permitir:
- Buscar el movimiento abierto del vehículo.
- Mostrar información de entrada.
- Calcular el tiempo de permanencia.
- Registrar fecha y hora de salida.
- Actualizar el estado de la celda a disponible.

### E. Historial
Mostrar los movimientos registrados con:
- Número de movimiento.
- Placa.
- Vehículo.
- Fecha y hora de entrada.
- Fecha y hora de salida.
- Estado.

Permitir consultar y filtrar los registros.

### F. Novedades
Permitir:
- Registrar novedades relacionadas con un vehículo.
- Escribir una descripción.
- Registrar fecha y hora.
- Consultar las novedades anteriores.

### G. Gestión de usuarios (Iteración 2)
Este módulo es exclusivo para empleados del parqueadero.

Permitir:
- Registrar usuarios internos.
- Consultar usuarios.
- Editar información.
- Activar o desactivar usuarios.
- Asignar roles y permisos.

Manejar inicialmente dos roles:

**Administrador:**
- Acceso a todos los módulos.
- Gestión de usuarios.
- Gestión de celdas.

**Operador:**
- Consultar vehículos.
- Registrar entradas y salidas.
- Consultar historial.
- Registrar novedades.

Datos del usuario:
- Identificador.
- Nombre completo.
- Correo electrónico.
- Contraseña.
- Rol.
- Estado.

Las contraseñas deben almacenarse de forma segura, nunca en texto plano.

### H. Gestión de celdas (Iteración 2)

Crear un módulo para administrar las celdas del parqueadero.

Permitir:
- Registrar nuevas celdas.
- Consultar las celdas existentes.
- Editar información.
- Activar o desactivar celdas.
- Consultar el estado de cada celda.
- Identificar qué vehículo ocupa una celda.

Cada celda debe tener:
- Identificador.
- Código o número de celda.
- Ubicación o descripción.
- Estado: Disponible, Ocupada o Inactiva.

Validaciones:
- No permitir códigos de celdas duplicados.
- No permitir asignar una celda ocupada a otro vehículo.
- No permitir ocupar una celda inactiva.
- Al registrar una entrada, actualizar la celda a Ocupada.
- Al registrar una salida, actualizar la celda a Disponible.

## 5. Base de datos

Revisa primero la estructura existente de MySQL, si hay una base de datos creada.

La primera iteración contempla las siguientes tablas:

- Vehiculo.
- Usuario.
- Movimiento.
- Novedad.

Para esta segunda iteración se debe ampliar el modelo incorporando la tabla Celda y ajustando las relaciones necesarias.

Revisa especialmente las relaciones entre Usuario, Vehiculo, Movimiento y Novedad.

No dupliques tablas ni crees entidades innecesarias.

Si ya existe una base de datos, conserva los datos y realiza las modificaciones necesarias mediante scripts SQL.

## 6. Organización del proyecto

Mantén separados el frontend y el backend.

Organiza el código por módulos y responsabilidades.

Utiliza:
- Componentes reutilizables en React.
- Rutas organizadas en Express.
- Controladores para manejar las operaciones.
- Modelos o consultas para acceder a MySQL.
- Validaciones de datos.
- Manejo básico de errores.

## 7. Instrucciones importantes

Antes de comenzar:

1. Inspecciona los archivos del proyecto y verifica si ya existe código.
2. Identifica qué funcionalidades están implementadas.
3. No elimines ni reemplaces funcionalidades existentes sin necesidad.
4. Conserva las tecnologías y la estructura que ya se estén utilizando.
5. Si encuentras inconsistencias, explícame cuáles son antes de modificar la base de datos.

Desarrolla el sistema por módulos, comenzando por la estructura general, el diseño de la interfaz y la conexión con la base de datos.

No quiero solamente pantallas de demostración: las operaciones de registro, consulta, edición y actualización deben funcionar y guardar información en MySQL.

Si alguna funcionalidad no está implementada, no la presentes como terminada.

Al finalizar cada módulo:
- Verifica que funcione.
- Corrige los errores encontrados.
- Indica qué archivos se crearon o modificaron.
- Explica cómo ejecutar el proyecto.

**Prioridad actual:** tener implementadas las funcionalidades de la Iteración 1 y especialmente la gestión de usuarios y la gestión de celdas de la Iteración 2.

Deja la estructura preparada para incorporar posteriormente el módulo de pagos.
